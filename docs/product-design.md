# 지역 기반 모임 앱 설계

작성일: 2026년 10월 25일 · 수정일: 2026년 10월 26일 · 상태: 확장 설계 · 서비스 가칭: 모여봄

관심사와 지역으로 모임을 찾고, 가입한 모임에서 대화하고, 정모에 참여하는 모바일 서비스를 만든다. 기본 이용 흐름은 소모임처럼 익숙하게 구성하고, 채팅의 대화 요약·특정인 발언 요약과 장소 등록·내부 길찾기를 핵심 차별점으로 둔다. 이 설계는 iOS·Android 앱을 대상으로 하며, 검토용 HTML 프로토타입으로 먼저 동작을 확인한다.

## 1. 설계 기준

소모임 공식 안내는 관심사·지역별 탐색, 모임 가입, 개별 정모 참여, 모임장·운영진, 게시판과 단체채팅을 구분한다. 이 서비스도 **모임은 지속되는 그룹, 정모는 날짜와 장소가 있는 개별 일정**으로 구분한다. 화면 배치와 세부 동작은 아래의 새 설계안으로 정의한다. [소모임 공식 안내](https://www.somoim.co.kr/helps)

대화 요약은 이미 제품 사례가 있다. 카카오는 채팅 대화 요약 기능을 소개하고 있으며, Slack은 안 읽은 대화·최근 대화·선택 기간 요약과 출처 확인을 제공한다. 이 설계는 해당 기능을 외부 서비스에서 가져오는 방식이 아니라, **우리 앱에 저장된 채팅을 우리 서버에서 요약하는 방식**이다. [카카오 공식 소개](https://www.kakaocorp.com/page/detail/12068), [Slack 공식 안내](https://slack.com/help/articles/25076892548883/Guide-to-AI-features-in-Slack)

| 구분 | 1차 설계 결정 |
| --- | --- |
| 이용 기기 | 휴대전화 우선, HTML 프로토타입은 데스크톱에서도 이용 가능 |
| 전체 메뉴 | 탐색 / 내 모임 / 채팅 / 마이 |
| 모임 화면 | 홈 / 게시판 / 사진첩 / 정모, 상단 멤버 목록, 빠른 채팅 진입 |
| 기본 채팅 | 모임당 공용 채팅방 1개와 정모별 참석자 전용 대화방 |
| AI 진입 | 안 읽은 대화 배너, 채팅 상단 AI 요약 버튼, 멤버 프로필의 발언 요약 |
| 요약 공개 | 요청한 사람에게만 표시 |
| 내부 지도 | 카카오맵 SDK 우선 |
| 내부 경로 | 카카오맵 도보·대중교통, 자동차는 카카오모빌리티 연동 |
| 외부 지도 | 카카오맵 / 네이버지도 선택 |
| 신규 가입자의 대화 | 기본은 가입 이후 대화부터 열람. 공지·정모는 별도 공개 범위 적용 |
| 현재 위치 | 사용자가 내 주변 탐색·거리순·장소 검색·길찾기를 요청할 때 해당 용도로 사용하며 다른 멤버에게 공유하지 않음 |

## 2. 전체 메뉴와 화면 구조

```text
가입 및 시작
 └ 로그인 → 프로필 → 활동 지역 → 관심사 선택

탐색
 ├ 지역 선택 / 관심사 / 검색 / 조건 필터
 ├ 추천 모임 / 가까운 모임 / 다가오는 정모
 └ 모임 상세 → 소개·가입조건 확인 → 가입 또는 가입신청

내 모임
 ├ 가입한 모임 / 신청 중 / 찜한 모임
 ├ 내 정모 일정
 └ 모임 상세
    ├ 홈: 소개, 공지, 다음 정모, 최근 활동
    ├ 게시판: 공지·가입인사·자유·정보·후기, 댓글
    ├ 사진첩: 앨범, 사진 상세
    ├ 정모: 목록·달력, 생성·수정, 상세, 참석·취소
    ├ 멤버: 프로필, 역할, 운영 관리
    └ 채팅: 공용 채팅방으로 이동

채팅
 ├ 채팅방 목록: 최근 메시지, 안 읽은 수, 알림 설정
 └ 채팅방
    ├ 텍스트·사진·정모/장소 카드·답장·멘션
    ├ 검색 / 공지 / 멤버 / 사진 모아보기
    ├ 최신 메시지로 이동
    └ AI 요약: 대화 요약 / 특정인 발언 요약

마이
 ├ 프로필 / 지역 / 관심사
 ├ 찜 / 내 활동 / 알림 설정
 └ 차단·신고 / 계정 설정
```

모임 상세는 네 개의 주요 탭을 유지해 가로 메뉴가 과밀해지지 않게 한다. 멤버는 상단 인원 표시에서, 채팅은 명확한 진입 버튼에서 연다. 채팅방은 대화에 집중하도록 전체 하단 메뉴를 접고 뒤로가기를 제공한다.

## 3. 모임과 정모

### 모임 탐색과 가입

모임 카드에는 대표 이미지, 모임명, 활동 지역, 대표 관심사, 현재 인원, 가입 방식, 다음 정모를 보여준다. 검색은 모임명·소개·태그를 대상으로 하고, 지역과 관심사 필터를 함께 적용한다. 거리순은 위치 권한이 있을 때 제공한다. 모임 카드는 활동 지역 대표점을 기준으로 `약 ○km · 지역 기준`을 표시하고, 다음 정모를 안내하는 카드에서는 해당 정모의 집결 위치를 기준으로 표시한다. 이 직선거리와 경로 API가 계산한 실제 이동거리·시간을 구분한다.

모임 생성 시 모임명, 소개, 대표 관심사, 활동 지역, 대표 이미지, 정원, 가입 방식, 가입 조건을 입력한다. 모임의 활동 지역은 행정구역 중심이고, 정모의 정확한 장소와 분리한다. 가입 방식은 즉시 가입 또는 승인 후 가입으로 정한다.

가입 상태는 `미가입 → 신청 중 → 가입 완료`와 `반려·취소·탈퇴·강퇴`를 구분한다. 중복 신청과 정원 초과는 서버에서 차단한다. 가입 대기자에게 비공개 게시글·사진·채팅·요약을 노출하지 않는다.

### 정모 등록과 참석

정모 필드는 제목, 설명, 시작·종료 시각, 정원, 참석 마감, 장소, 상세 집결 위치, 비용 안내, 준비물이다. 비용 안내는 텍스트이며 실제 결제·정산과 분리한다.

등록 흐름은 `내용·일시 입력 → 장소 검색 → 결과 선택 → 지도에서 위치 확인 → 상세 집결 위치 입력 → 등록`이다. 한 모임 안에서도 각 정모의 장소가 달라질 수 있다. 참석·취소는 인원수와 함께 즉시 반영하고, 마지막 한 자리에 여러 명이 신청하면 서버 트랜잭션으로 정원을 지킨다.

장소나 시간이 바뀌면 정모의 버전을 갱신하고 참석자에게 알린다. 연결된 채팅 카드도 최신 정모 정보를 연다. 이전 채팅과 요약에서 다룬 일정은 해당 시점의 정보임을 구분한다. AI가 채팅을 요약했다고 정모 정보가 자동으로 바뀌지는 않는다.

### 운영 권한

| 행동 | 미가입/대기 | 멤버 | 운영진 | 모임장 |
| --- | --- | --- | --- | --- |
| 공개 소개와 공개 정모 보기 | 가능 | 가능 | 가능 | 가능 |
| 멤버 전용 활동·채팅·AI 요약 | 불가 | 가능 | 가능 | 가능 |
| 게시글·사진·댓글 작성 | 불가 | 가능 | 가능 | 가능 |
| 정모 참석·취소 | 불가 | 가능 | 가능 | 가능 |
| 정모 생성·관리, 공지 등록 | 불가 | 불가 | 가능 | 가능 |
| 가입 승인·신고 처리·멤버 관리 | 불가 | 불가 | 가능 | 가능 |
| 운영진 임명·해제, 모임장 위임 | 불가 | 불가 | 불가 | 가능 |

작성자는 자신의 게시글·메시지를 삭제할 수 있고 운영진은 운영 목적으로 삭제할 수 있다. 삭제 흔적은 남기되 본문·첨부파일은 다른 사용자에게 제공하지 않는다. 모임장 탈퇴는 위임을 거쳐 처리한다. 일반 멤버의 정모 생성 허용은 후속 운영 옵션이다.

## 4. 익숙한 채팅 경험

### 화면 구성

상단에는 뒤로가기, 모임명·인원, 검색, AI 요약, 더보기를 둔다. 공지가 있으면 한 줄로 접어 보여준다. 대화 영역에는 날짜 구분, 프로필·이름, 좌우 말풍선, 전송 시각, 읽지 않은 인원 표시를 둔다. 하단에는 첨부 버튼, 입력창, 전송 버튼을 배치한다.

| 기능 | 동작 |
| --- | --- |
| 텍스트 | 줄바꿈 입력, 명시적인 전송 버튼, 전송 중·완료·실패 상태 |
| 이미지 | 갤러리/카메라 → 선택 미리보기 → 전송, 썸네일·확대 보기·실패 재시도 |
| 답장 | 원문 미리보기와 원문 이동, 원문 삭제 시 삭제 상태 표시 |
| 멘션 | 멤버 선택으로 작성, 대상에게 알림 |
| 메시지 메뉴 | 복사, 답장, 신고, 본인 삭제, 운영 삭제 |
| 검색 | 키워드·작성자·기간, 결과에서 해당 메시지로 이동 |
| 최신으로 이동 | 과거 대화를 볼 때 입력창 위에 `↓ 최신 대화` 버튼 표시 |
| 새 메시지 | 과거를 읽는 중이면 이동시키지 않고 새 대화 수 표시 |
| 과거 대화 | 위로 스크롤하면 커서 기준 추가 조회, 읽던 위치 유지 |

입장 시 안 읽은 메시지가 있으면 첫 안 읽은 위치를 우선 보여준다. 최신 위치 부근에 있을 때만 새 메시지 도착 시 자동으로 아래로 이동한다. `최신 대화`는 현재 로드된 목록의 끝이 아니라 **서버의 실제 최신 메시지**까지 조회해 이동한다.

이미지는 가로·세로 크기를 먼저 확보해 로딩 중 스크롤이 튀지 않게 한다. 원본·썸네일은 접근 권한이 있는 사용자만 볼 수 있도록 한다. 업로드 파일의 실제 형식·용량을 서버에서 검사하고, 실패한 사진만 따로 재시도할 수 있게 한다.

읽음은 실제 메시지를 확인한 위치를 기준으로 기록한다. 안 읽은 요약만 본 경우 해당 대화를 모두 읽은 것으로 바꾸지 않는다. 여러 기기에서 읽으면 가장 큰 읽음 커서를 유지한다.

## 5. AI 대화 요약

### 진입과 범위

안 읽은 메시지가 일정량 쌓이면 `안 읽은 대화 128개 · 요약 보기` 배너를 보여준다. 표시 기준 30개는 초기 제안값이며 제품 운영 중 조정한다. 메시지가 적어도 상단 AI 버튼에서 직접 요약할 수 있다.

요약 패널에는 **대화 요약 / 특정인 발언** 탭과 **안 읽은 대화 / 오늘 / 최근 7일 / 기간 선택**을 둔다. 여기서 대화 요약은 선택 기간의 모든 참여자를 대상으로 한다는 뜻이다. 전체 보관 기간을 선택할 때는 처리 범위를 표시하고 비동기 작업으로 진행한다. 긴 범위를 조용히 잘라내지 않는다.

결과에는 적용 기간, 포함 메시지 수, 생성 기준 시각, 제외된 자료 범위, `AI 생성 요약` 표시를 둔다. 패널은 채팅 위에 열고 닫으면 읽던 위치로 돌아간다. 생성 중에도 채팅을 계속 이용할 수 있다.

### 대화 요약 결과

읽는 부담을 줄이기 위해 첫 화면에는 핵심 3~5개를 보여주고 필요할 때 더 펼친다. 항목은 다음 구조를 권한다.

| 항목 | 출력 예 |
| --- | --- |
| 핵심 흐름 | 이번 주 러닝 시간과 집결 장소를 논의함 |
| 확정된 내용 | 운영진이 19시 시작으로 확정함 · 원문 보기 |
| 제안·미정 | 종료 후 식사는 후보만 나왔고 확정되지 않음 · 원문 보기 |
| 일정·장소 변경 | 집결 장소 변경 안내가 있었음 · 원문 보기 |
| 내가 확인할 내용 | 공지에서 준비물 확인 필요 · 원문 보기 |

예시는 출력 형식이며 실제 앱에서는 반드시 원문에 근거한 항목만 생성한다. 근거가 없는 항목은 생략한다. 참석 의사를 질문한 문장을 참석 확정으로 바꾸거나, 한 사람의 제안을 모임 전체의 결정으로 바꾸지 않는다. 앞뒤에서 의견이 바뀌면 최신 발언과 변경 흐름을 함께 반영한다.

`원문 보기`는 실제 근거 메시지로 이동해 잠깐 강조한다. 요약 패널을 다시 열면 이전 결과와 조건을 유지한다. 요약을 공유하려면 별도 공유 동작과 내용 확인을 거치며, 최초 버전에서는 요청자 개인 보기만 제공한다.

### 특정인 발언 요약

채팅의 프로필을 누르거나 요약 패널에서 멤버를 선택한다. 같은 닉네임을 가진 사람은 프로필과 모임 역할로 구별한다. 대상 변경 시 이전 결과를 새 대상의 결과처럼 보여주지 않는다.

처리 순서는 `대상 user_id 확인 → 열람 가능한 메시지 중 author_id 일치 필터 → 기간 적용 → 요약`이다. 다른 사람이 그 사람을 멘션하거나 인용한 메시지를 그 사람의 발언으로 포함하지 않는다. 본문에 포함된 타인의 인용도 대상자가 직접 주장한 내용과 구분한다.

결과는 대상자의 주요 발언, 요청·공지, 본인이 명시한 참석 여부·시간·준비사항 등을 보여준다. 성격·감정·속마음을 추정하거나 사람을 평가하는 분석은 포함하지 않는다. 문맥이 필요하면 열람 가능한 답장 원문을 보조 자료로 쓰되 타인의 말임을 표시한다. 대상 발언이 없으면 `선택한 기간에 이 멤버의 발언이 없습니다`를 보여준다.

### 정확도와 처리 구조

1. 서버가 요청자의 현재 멤버십과 원문 접근 범위를 확인한다.
2. 요청 순간의 읽음 커서·마지막 메시지 순번·기간·대상자를 고정한다.
3. 삭제·숨김·접근 불가 메시지와 지원하지 않는 이미지 본문을 제외한다.
4. 시간 흐름과 답장 관계를 유지해 대화를 나눈다. 긴 대화는 구간별 처리 후 통합한다.
5. 각 요약 항목에 근거 message_id를 유지한다. 숫자·일정·확정 여부를 검증하고 결과를 저장한다.
6. 결과를 제공하기 직전에 접근 권한과 원문 버전을 다시 확인한다.

채팅에 적힌 명령문은 요약 대상 데이터로만 다룬다. AI가 외부 도구를 실행하거나 모임 정보를 수정하지 않는다. 텍스트와 사진 설명은 1차 요약 대상이며 사진 속 내용·음성·영상 분석은 별도 확장 기능이다. 사진을 제외했다면 결과에 그 범위를 표시한다.

처리 상태는 `대기 → 생성 중 → 완료`와 `요약할 대화 없음 / 실패 / 사용량 제한`으로 구분한다. 생성 중 도착한 새 메시지는 기존 결과의 범위를 바꾸지 않고 `새 대화가 있습니다 · 다시 요약`으로 알린다.

요약 접근은 원문 접근과 같아야 한다. 탈퇴·강퇴, 차단에 따른 숨김, 원문 삭제·수정, 공개 범위 변경 시 해당 결과를 무효화한다. 캐시 키에는 요청자, 채팅방, 열람 범위 버전, 차단 상태 버전, 기간, 대상자, 기준 순번, 원문 변경 버전, 모델·프롬프트 버전을 포함한다. 권한이 다른 사용자에게 결과를 그대로 공유 캐시하지 않는다.

AI 사용 안내와 필요한 동의, 외부 모델 업체의 보관·학습 조건을 실제 연동 전에 확정한다. 원문 전체를 앱 로그에 남기지 않으며 사용자에게 결과 삭제 기능을 제공한다. 과도한 반복 호출은 동일 조건 재사용·요청 병합·사용량 제한으로 제어한다.

## 6. 장소 등록과 지도

### 권장 연동

**카카오로 장소 검색·내부 지도·도보 및 대중교통 경로를 통일**하고, 자동차 경로에는 카카오모빌리티를 사용한다. 네이버지도와 카카오맵으로 여는 버튼을 함께 제공한다. 이 선택은 공식 API 지원 범위와 한 제공사 안에서의 데이터 연결을 고려한 설계 권고다.

| 기능 | 권장 API/SDK | 화면 동작 |
| --- | --- | --- |
| 장소 검색 | 카카오맵 키워드·카테고리 검색 | 이름·주소 검색, 주변 후보, 결과 목록 |
| 주소/좌표 | 카카오맵 주소 변환 | 도로명/지번 주소, 좌표 확인 |
| 내부 지도 | 카카오맵 Web / Android / iOS SDK | 핀, 확대·축소, 내 위치·집결 위치 |
| 도보 경로 | 카카오맵 `/v2/routing/walk` | 경로선, 거리·시간, 단계 안내 |
| 대중교통 경로 | 카카오맵 `/v2/routing/publictraffic` | 경로선, 탑승·환승·하차, 제공되는 요금·시간 |
| 자동차 경로 | 카카오모빌리티 일반 길찾기 | 경로선, 예상 시간·거리, 외부 내비 진입 |
| 외부 지도 | 지도앱 URL 스킴·웹 링크 | 목적지를 채워 지도/길찾기 열기 |

카카오맵 공식 REST 문서는 도보·대중교통 경로와 좌표 목록을 제공한다. 지도 SDK에 이 좌표를 그려 내부 경로 화면을 구현한다. 네이버의 확인한 공개 Directions 5 문서는 자동차 경로 API이므로, 이 문서를 근거로 내부 도보·대중교통까지 제공된다고 가정하지 않는다. [카카오맵 REST](https://developers.kakao.com/docs/ko/kakaomap/rest-api), [카카오맵 SDK 안내](https://developers.kakao.com/docs/ko/kakaomap/common), [네이버 Directions 5](https://api.ncloud-docs.com/docs/application-maps-directions5), [카카오모빌리티 시작하기](https://developers.kakaomobility.com/guide/navi-api/start.html)

### 장소 선택

검색 결과에서 장소명, 도로명 주소, 현재 기준 위치와의 거리를 확인한다. 검색어가 없거나 결과가 없으면 주소 검색 또는 지도 핀 지정으로 전환한다. 사용자가 지도를 옮겼을 때만 `이 지역에서 다시 검색`을 제공하고, 이동할 때마다 자동 검색하지 않는다.

선택 후에는 지도 핀과 `정문 앞 / 2번 출구 / 건물 3층` 같은 상세 집결 위치를 함께 확인한다. 제공자 장소의 중심점과 실제 집결 좌표를 구분해 저장하고, 내부 지도·외부 길찾기는 최종 확정된 집결 좌표를 목적지로 사용한다.

### 내부 미니 지도와 길찾기

정모 상세에는 미니 지도, 장소명, 주소, 집결 설명, `경로 보기`, `카카오맵`, `네이버지도`를 둔다. 목록에서는 무거운 지도를 반복 생성하지 않고 카드 텍스트·허용되는 정적 미리보기로 표시한다.

`경로 보기 → 현재 위치 허용 또는 출발지 직접 선택 → 이동 수단 선택 → 경로 조회`로 연결한다. 지도에 출발·도착 핀과 경로선을 보여주고 하단에 시간·거리·대중교통 환승 정보를 표시한다. 위치 권한이 없거나 위치를 못 받으면 출발지를 검색해서 정할 수 있다.

현재 위치 점과 경로 조회에 사용한 출발지를 구별한다. 이동 후 사용자가 `현재 위치에서 다시 찾기`를 누르면 재조회한다. 이동 경로 확인은 1차 범위이며, 실시간 음성 안내·백그라운드 내비게이션은 외부 지도 앱으로 연결한다.

지도 로딩 실패, API 사용량 초과, 경로 없음, 위치 권한 거부, 외부 지도 앱 미설치 상태에서 주소 복사·출발지 변경·웹 지도 열기를 제공한다. 실패한 경로 대신 직선을 그려 실제 이동 경로처럼 표시하지 않는다.

외부 네이버지도 스킴에는 앱 식별자를 넣고 미설치 처리를 구현한다. 카카오맵도 공식 스킴 또는 응답의 연결 URL을 사용한다. REST 키는 서버에서 관리하고, 지도 SDK용 공개 키는 플랫폼·도메인·앱 식별자 제한을 적용한다. [네이버지도 스킴](https://guide.ncloud-docs.com/docs/application-maps-url-scheme-vpc), [카카오맵 스킴](https://apis.map.kakao.com/ios_v2/docs/getting-started/urlscheme/)

지도 사용량은 지도 로드·장소 검색·수단별 경로 조회를 분리해 관측한다. 무료 쿼터 적용 조건과 초과 요금은 계정·앱 설정에 따라 확인하고 실제 트래픽으로 비용을 산정한다. 제공자 데이터의 저장·캐시·출처 표시는 해당 이용 조건에 맞춘다. [카카오 이용 조건 안내](https://developers.kakao.com/docs/ko/kakaomap/common), [카카오 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota), [카카오모빌리티 요금](https://developers.kakaomobility.com/price/)

## 7. 서버와 데이터 구조

초기에는 인증·모임·정모·게시판·채팅·장소 기능을 모듈로 나눈 서버와 관계형 DB를 사용한다. 실시간 채팅 연결, 이미지 저장소, AI 비동기 작업자를 분리한다. 앱은 영구 저장과 이력 조회에 HTTP API를, 메시지·읽음 갱신에는 실시간 연결을 사용한다.

```text
모바일 앱 / 검토용 HTML
 ├ HTTP API → 인증·모임·게시판·정모·장소 모듈 → 관계형 DB
 ├ 실시간 연결 → 채팅 모듈 → 메시지 DB·이벤트 발행
 ├ 업로드 API → 비공개 이미지 저장소·썸네일 처리
 ├ 요약 요청 → 작업 큐 → AI 작업자 → 모델 API → 근거 검증·결과 저장
 └ 지도 SDK + 서버 지도 어댑터 → 카카오맵·카카오모빌리티
```

| 데이터 | 주요 필드·관계 |
| --- | --- |
| User | id, 프로필, 지역, 관심사 |
| Category / Region | 관심사 계층·태그, 행정구역 |
| Group | id, owner_id, category_id, region_id, 가입 방식, 정원 |
| GroupMembership / JoinRequest | group_id, user_id, 역할, 상태, 가입·탈퇴 이력 |
| Post / Comment / Album | group_id, author_id, 공개 범위, 본문, 첨부 |
| Event | group_id, 시작·종료·마감, 정원, 상태, 장소 스냅샷, version |
| EventAttendance | event_id, user_id, 신청·취소·참석 상태, 유일키 |
| Place / MeetingPoint | provider, provider_place_id, 장소명·주소, 좌표, 집결 좌표·설명 |
| ChatRoom / ChatMembership | group_id, 멤버별 열람 시작 순번·권한 버전 |
| Message | room_id, room_seq, author_id, client_message_id, type, 본문, reply_to, 변경 버전 |
| Attachment | message_id, 저장키, 형식·용량·크기, 썸네일, 처리 상태 |
| ReadCursor | room_id, user_id, last_read_seq |
| SummaryRequest / SummaryItem | requester_id, room_id, mode, target_user_id, 범위·기준 순번, 상태, 결과 |
| SummarySource | summary_item_id, message_id, 원문 버전 |
| Report / Block / Notification | 신고 대상·처리 상태, 차단 관계, 알림·기기 토큰 |

정모에는 사용자 지정 집결 위치와 등록 당시 선택 장소 정보를 연결한다. 장소 사업자의 데이터가 변경되어도 등록한 정모의 설명이 임의로 바뀌지 않게 하되, 사업자 데이터의 보관은 이용 정책을 따른다. 현재 GPS 좌표는 정모 데이터에 저장하지 않는다.

### 채팅 정합성

서버 저장 성공 응답 후에 전송 완료로 표시한다. `(room_id, author_id, client_message_id)` 유일키로 재전송 중복을 막고, 채팅방별 단조 증가 `room_seq`로 정렬·커서 페이지네이션·재접속 동기화를 처리한다. 저장과 이벤트 발행 사이의 유실은 outbox 또는 동등한 방식으로 방지한다.

클라이언트는 재연결 시 마지막 수신 순번 이후를 다시 받으며 message_id로 중복을 제거한다. 읽음 커서는 감소시키지 않는다. 탈퇴·강퇴 시 실시간 구독과 파일·요약 접근을 함께 해제한다. 비공개 자료는 화면 숨김에만 의존하지 않고 서버에서 권한을 검사한다.

| `POST /rooms/{id}/summaries` | 범위·대상 기준 요약 작업 생성 |
| `GET /summaries/{id}` | 상태·결과·원문 근거 조회 |
| `GET /places/search?q=&lat=&lng=` | 장소·주소 검색 |
| `POST /routes` | 출발·도착·이동 수단 기준 경로 |

실시간 이벤트는 `message.created`, `message.deleted`, `read.updated`, `summary.completed`, `event.updated`, `membership.changed`를 기본으로 한다. API의 모든 group_id·room_id·message_id는 요청자 접근 권한으로 검증한다.

## 8. 구현 순서와 범위

| 단계 | 완료할 기능 | 완료 판단 |
| --- | --- | --- |
| HTML 검토 | 탐색·모임 상세·채팅·요약·정모·장소 등록 흐름 | 샘플 데이터로 클릭·입력·상태 전환 가능 |
| 기반 구현 | 로그인, 프로필, 모임·가입·운영, 게시판·사진첩, 정모·참석 | 실제 계정·권한·DB로 전체 흐름 연결 |
| 채팅 | 실시간 메시지, 이미지, 읽음, 검색, 알림, 최신 이동 | 재접속·재전송·스크롤·사진 실패 처리 확인 |
| AI | 대화·특정인 요약, 기간, 원문 이동, 삭제·권한 반영 | 실제 모델 평가와 데이터 접근 검증 통과 |
| 지도 | 장소 검색·등록, 미니 지도, 내부 경로, 외부 지도 | 실제 키·GPS·실기기에서 지원 수단별 검증 |
| 출시 준비 | 신고·차단·탈퇴·운영, 성능, 사용량·비용 관측 | 주요 예외 상태와 모바일 검증 통과 |

1차 출시에는 위 기본 기능과 사용자가 요청한 AI·내부 지도 경로를 모두 포함한다. 개발 중간 단계에서 지도·요약을 외부 링크만 있는 상태로 완료 처리하지 않는다.

정모별 참석자 대화방, 답장·멘션·이모지, 게시판 이미지·댓글, 프로필 사진 관리, 모임 꾸미기와 이미지 공지는 확장된 1차 범위에 포함한다. 후속 기능은 개인 채팅, 음성·영상, 회비 결제·정산, 실시간 위치 공유, 고급 자동 추천, 요약 자동 공유·정기 브리핑이다. 소모임의 유료 이용권이나 클래스 사업 구조까지 동일하게 적용할지는 별도 사업 결정이다.

## 9. 수용 기준

1. 관심사와 지역을 함께 선택해 모임을 찾고 가입 방식에 맞게 가입할 수 있다.
2. 모임과 정모를 별도로 생성·조회하고, 참석·취소 시 정원이 지켜진다.
3. 과거 대화를 읽을 때 새 메시지·이미지 로딩이 위치를 강제로 바꾸지 않는다.
4. 최신 이동 버튼으로 서버의 실제 마지막 메시지에 도달한다.
5. 끊어진 연결에서 재접속하면 누락을 복구하고 재전송해도 중복 저장하지 않는다.
6. 이미지를 선택·확인·전송·확대하고 실패한 파일을 재시도할 수 있다.
7. 안 읽은 요약 범위가 생성 중 바뀌지 않고 요약 열람만으로 읽음이 처리되지 않는다.
8. 같은 닉네임·닉네임 변경·멘션·인용 상황에서도 특정인 발언의 작성자가 섞이지 않는다.
9. 요약의 결정·미정·변경 내용이 원문과 일치하고 항목별 근거로 이동한다.
10. 발언 없음·긴 대화·이미지 제외·AI 실패 상태를 명확하게 보여준다.
11. 삭제한 원문이나 권한을 잃은 대화가 예전 요약·첨부 링크로 노출되지 않는다.
12. 등록한 집결 위치와 내부 지도·외부 길찾기의 목적지가 일치한다.
13. 내부 도보·대중교통·자동차 경로가 실제 API 응답과 일치한다.
14. 위치 거부·경로 없음·지도 실패·외부 앱 미설치에서도 대체 동작을 제공한다.
15. 작은 모바일 화면에서도 입력창·요약·정모 폼과 접근성 조작이 가능하다.

## 10. HTML 프로토타입과 실제 서비스의 경계

프로토타입은 계정 없이 샘플 모임과 대화로 이용 흐름을 검토한다. 검색·가입·찜·채팅 입력·로컬 사진 미리보기·멤버 선택·요약 조건·원문 이동·정모 참석·장소 선택은 브라우저에서 동작하게 만든다. 화면에서 `프로토타입`과 `예시 요약`을 표시한다.

HTML에서는 모임 만들기와 이미지 확대도 제공한다. 대표 카테고리·샘플 장소로 흐름을 검토하며, 요약 기간은 안 읽은 대화·오늘·최근 7일을 제공한다. 채팅은 최신 위치로 열고 입장 시점의 안 읽은 범위를 별도로 유지한다. 사용자가 선택한 임의 기간, 신규 가입자의 실제 권한, 승인제 신청 심사는 서버 구현 단계에서 연결한다.

요약은 수백 건의 데모 대화의 발췌·규칙 처리로 구현하며 외부 AI 모델을 호출하지 않는다. 지도에는 목적지가 보이는 실제 지도 스크린샷과 이동 수단·출발지 선택 흐름을 보여주고 외부 지도 열기를 연결한다. 실제 동적 지도·GPS 경로·실시간 다자간 채팅·서버 권한·원격 푸시·서버 파일 저장은 다음 구현 단계다. 시연용 로컬 상태는 서버 보안이나 실제 서비스 완성도를 증명하지 않는다.

실제 연동 전에 확정할 항목은 모바일 프레임워크와 서버 운영 환경, AI 모델과 처리·보관 조건, 지도 사업자 앱·키·예산, 메시지 보관 기간, 가입 이전 채팅의 공개 범위다. 현재 문서의 기본값으로 프로토타입을 진행하고 이후 실제 운영 조건에 맞춰 조정한다.

2026년 10월 26일 추가한 정모 대화방, 멘션·답장, 수백 건 요약, 이미지 게시판과 프로필 관리, 웹·모바일 화면의 구체적인 동작은 [확장 상호작용 설계](interaction-design-v2.md)를 따른다.
